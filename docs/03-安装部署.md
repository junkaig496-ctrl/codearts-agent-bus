# 03 · 安装部署（码道 IDE / CLI / 插件）

> 全程约 5 分钟。**不需要安装任何 Python 第三方库**（纯标准库）。

## 〇、前置检查

```bash
python -V          # 需要 Python 3.10+（本机实测 3.13）
python tests/test_e2e.py     # 在项目目录里跑，看到「全部通过 ✅」再继续
```

如果 `python` 命令不可用，用绝对路径，例如：
`C:\Users\<用户名>\AppData\Local\Programs\Python\Python313\python.exe`

## 方式 A：stdio（推荐，码道 IDE / CLI / VS Code 插件）

### 步骤 1｜安装技能（让智能体"会"用总线）

把项目里的 `skills/agent-bus` 整个目录拷到下面任一处：

| 作用范围 | 目标路径 |
|---|---|
| 只给当前项目用 | `<你的项目根目录>\.codeartsdoer\skills\agent-bus\` |
| 给本机所有项目用 | `C:\Users\<用户名>\.codeartsdoer\skills\agent-bus\` |

最终结构必须是：

```
.codeartsdoer/skills/agent-bus/SKILL.md      ← 注意目录名与 name 字段都要是 agent-bus
```

拷完在码道里打开：**设置 → 技能与规则 → 个人级 / 项目级**，确认能看到 `agent-bus` 且为「已开启」。

### 步骤 2｜配置 MCP（让码道"能"访问总线）

**方式一（推荐，直接写文件）**：按码道真实的配置文件位置落盘（实测自码道 IDE 26.9.102 的程序代码）：

| 作用范围 | 配置文件真实路径 |
|---|---|
| 只给当前项目 | `<项目根目录>\.codeartsdoer\mcp\mcp_settings.json` |
| 本机所有项目 | `C:\Users\<用户名>\.config\opencode\mcp\mcp_settings.json` |

**方式二（图形界面）**：码道 IDE 右上角 ⚙ 设置 → 左侧 **MCP工具** → **配置MCP**，会打开 `mcp_settings.json`。**

两种方式写入的都是同一份 JSON，把下面这段**合并**进 `mcpServers` 里（不要整体覆盖，你已有的 MCP 要保留）：

```json
{
  "mcpServers": {
    "agent-bus": {
      "command": "C:\\Users\\刹那酸语\\AppData\\Local\\Programs\\Python\\Python313\\python.exe",
      "args": [
        "C:\\Users\\刹那酸语\\Desktop\\codearts-agent-bus\\src\\bus_mcp.py"
      ],
      "env": {
        "PYTHONIOENCODING": "utf-8",
        "AGENT_BUS_HOME": "C:\\Users\\刹那酸语\\.codeartsdoer\\agent-bus"
      }
    }
  }
}
```

> 已有其他 MCP 的合并范例见 `config/mcp_settings.merged-example.json`。

3. `Ctrl+S` 保存，等工具启动完成。**设置 → MCP工具 → 已安装** 里应出现 `agent-bus`。

> 实测补充：码道会在技能目录里"挂载"技能（日志可见 `Mounted … skill … to C:\Users\<用户名>\.codeartsdoer\skills\…`），
> 所以个人级技能放 `~/.codeartsdoer/skills/` 是官方认可的位置。

**两个必须注意的点**

* `command` 建议写 **python 绝对路径**（避免码道拉起的子进程找不到 `python`）。
* **不要在 `env` 里写 `AGENT_BUS_NAME`**：多个会话共用这一份配置，写死会让所有会话撞成同一个身份。
  身份由智能体在会话内用 `bus_register(name=...)` 自己声明。

### 步骤 3｜验证

在码道任意会话的聊天框里说：

> 调用 bus_register，名字叫 planner，角色 leader；然后用 bus_ps 看看总线上有谁。

预期：返回里出现 `session_id: planner-xxxxxx` 和会话列表。

命令行侧另开一个窗口再验一次：

```bash
python src/bus_cli.py ps        # 应能看到刚才注册的码道会话
```

## 方式 B：StreamableHTTP / SSE（码道 Space 模式、网页版、远程）

stdio 拿不到本地进程的场景用这条。

```bash
python src/bus_http.py --port 8765
```

启动后终端会打印（含自动生成的 token）：

```json
{
  "mcp_endpoint": "http://127.0.0.1:8765/mcp?token=xxxxxxxx",
  "streamable_http_config": {
    "agent-bus": { "url": "http://127.0.0.1:8765/mcp?token=xxxxxxxx", "type": "streamableHttp" }
  },
  "dashboard": "http://127.0.0.1:8765/dashboard?token=xxxxxxxx"
}
```

把 `streamable_http_config` 那一段合并进 `mcp_settings.json` 即可（把 `type` 换成 `"sse"` 亦可）。
健康检查：`curl http://127.0.0.1:8765/health`。

> 安全：默认只监听 `127.0.0.1` 且强制 token；除 `/health` 外都需要 token。
> 想让局域网里别的设备接入，自行加 `--host 0.0.0.0` 并评估风险。

2. 删掉 `.codeartsdoer\skills\agent-bus`；
3. （可选）删掉状态目录 `C:\Users\<用户名>\.codeartsdoer\agent-bus`。
   码道与其数据不受任何影响 —— 全程没有修改码道自身文件。

## 故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| MCP 已安装但工具列表里没有 bus_* | 启动进程失败（大多是 `command` 路径不对） | 把 `command` 换成 python 绝对路径；先在终端手跑 `python src/bus_mcp.py` 看是否正常等待输入（不报错即正常，`Ctrl+C` 退出） |
| 返回里中文乱码 | 子进程编码不是 UTF-8 | 确认 `env` 里有 `PYTHONIOENCODING=utf-8` |
| 智能体说"找不到会话 xxx" | 对方还没 `bus_register`，或已离线（>90s 无心跳） | 用 `bus_list_peers(include_offline=true)` 看全量；让对方重新注册 |
| worker 一直说"暂无待领任务" | 它没在待命，或任务派给了别的名字 | 让 worker 调 `bus_next_task(wait_seconds=60)`；leader 用 `bus_list_peers` 核对 `to` 的名字 |
| leader 收不到回执 | leader 没有主动取信（MCP 不会推消息） | 让 leader 调 `bus_inbox(wait_seconds=60)`，或 `bus_list_tasks` 直接看状态 |
| 报"bus.lock 获取超时" | 另一个进程卡在锁里（极少见，多见于被强杀的进程） | 稍等重试；确认没有几十个僵尸 MCP 进程（任务管理器搜 `python.exe`） |
| 技能不触发 | 技能没被码道识别 | 检查目录名与 `SKILL.md` 里的 `name` 是否都是 `agent-bus`；在设置页确认状态为"已开启"；对话里可直接点名："使用 agent-bus 技能" |
| `AGENT_BUS_HOME` 设成 `\c\Users\...` 这种路径 | 用 MSYS/git-bash 风格路径传给了 Python | 用 Windows 原生路径（`C:\Users\...`） |
