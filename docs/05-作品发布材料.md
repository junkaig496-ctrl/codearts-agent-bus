## 二、作品简介（可直接粘贴到发布表单）

> **背景**：码道官方支持同时开启多个会话并行开发（个人体验版 ≤3 个，标准版及以上 ≤5 个），
> 也提供了 AgentTeam 多智能体协作引擎。但我们在官方《用户指南（码道 IDE）》247 页全文中检索发现，
> 与"会话间通信"相关的关键词（`会话间`、`跨会话`、`消息总线`、`IPC`、`广播`）命中数**全部为 0**：
> 会话彼此"看不见、喊不应"，跨会话的分工只能靠人工复制粘贴。同时 AgentTeam 仅支持在
> Space 模式使用，IDE 模式下没有协作能力。
>
> **作品**：agent-bus 是一个本地会话总线。它以官方支持的两种扩展点落地 ——
> **MCP 服务器**（提供 17 个工具）与**技能**（SKILL.md 协作协议），不改动码道任何代码。
> 装上之后：一个会话可以当调度者把任务拆成子任务派发出去，其他会话通过阻塞式待命领活、
> 上报进度、提交回执，结果自动回传给派发方并汇总；全过程生成本地看板可视化。
>
> **对标**：本作品直接对标 Claude Code 泄露源码中尚未发布的 `UDS Inbox`（跨会话 IPC：
> 会话互发消息 + `ListPeersTool` 同伴发现）与 `Daemon Mode`（`docker ps` 式会话守护视图）。
>
> **工程**：纯 Python 标准库，零第三方依赖；自研跨进程文件锁（含 Windows 强制锁的**可重入**处理）
> 与原子写，保证多会话并发读写不丢不重；MCP 协议层手写实现（stdio + StreamableHTTP/SSE 双通道，
> 覆盖 IDE、CLI、插件与 Space/网页版）。35 项自动化检查全通过，含真实 MCP 子进程协议握手与
> 6 进程并发压测。

## 三、作品亮点（评审最关心的 6 条）

1. **补的是生态空白，不是重复造轮子**：缺口论证有官方文档证据（247 页全文关键词命中为 0），
   不与官方任何功能重叠。
2. **零侵入、可卸载**：只用官方 MCP + 技能扩展点，不修改码道一行代码，删除配置即完全恢复。
3. **真的能跑**：35 项自动化检查全通过 —— 包含真实拉起 MCP 子进程做 JSON-RPC 握手、
   6 进程并发写不丢不重、长轮询与租约回收等硬指标。
4. **服务端长轮询解决"MCP 不能主动推消息"的行业性难题**：把"待命"变成一次工具调用，
   让"派活—领活"闭环真正成立。
5. **两种传输通道**：stdio 覆盖 IDE/CLI/插件，StreamableHTTP/SSE 覆盖 Space 与远程接入。
6. **可演示、可复用、可扩展**：自带看板与一键演示剧本；任何码道用户装上即可用；
   后续可平滑接入 Hooks 做 token/成本看板（对标 `/ctx-viz`、`TOKEN_BUDGET`）。

## 四、技术栈

| 层 | 说明 |
|---|---|
| 扩展方式 | 华为云码道 MCP 服务器（stdio / StreamableHTTP / SSE）+ 码道技能（SKILL.md） |
| 语言 | Python 3.10+（纯标准库：json / socket / http.server / msvcrt·fcntl / tempfile） |
| 协议 | MCP（JSON-RPC 2.0，stdio 行分隔帧 + HTTP 单次响应） |

| 编排 | 任务状态机（pending→running→done/failed）+ 租约回收 + 长轮询待命 |
| 可视化 | 自包含单页 HTML 看板（SVG 拓扑 + 任务看板 + 消息流，无外链、离线可看） |

## 五、使用说明（简版，写进作品说明）

1. **装技能**：把 `skills/agent-bus` 拷到 `<项目>/.codeartsdoer/skills/`（或 `%USERPROFILE%/.codeartsdoer/skills/`）。
2. **配 MCP**：设置 → MCP工具 → 配置MCP，把 `config/mcp_settings.stdio.json` 里的 `agent-bus`
   合并进 `mcpServers`，`Ctrl+S` 保存。
3. **用起来**：每个会话先 `bus_register(name="…", role="leader|worker")`；
   leader 用 `bus_dispatch` 派活，worker 用 `bus_next_task(wait_seconds=60)` 待命领活、
   `bus_report` 回执，最后 `bus_dashboard` 生成看板。
4. 完整步骤与故障排查见 `docs/03-安装部署.md`；演示台词见 `docs/04-演示脚本.md`。

## 八、加分实证：让码道自己的智能体参与开发（建议写进简介）

本作品在开发末期做了一次反向验证：**让码道 IDE 里的智能体通过本总线领活**，
承担"为 `src/bus_core.py` 编写标准库 unittest 单元测试"这一真实子任务。

结果（均有总线日志与文件为证）：

* 码道智能体 `codearts-worker` 注册 → `claim` 领活 → 3 次 `bus_progress` 上报 → 产出
  `tests/test_bus_core_unit.py`（248 行 / 5 TestCase / 12 用例）；
* 它写出的测试**暴露了本项目的 2 个真实缺陷**：① Windows 上 `os.replace` 原子写撞并发读抛
  `PermissionError(13)`；② `list_tasks()` 只读视图存在写副作用（把租约回收事件消费掉）。
  两者已修复并补了回归测试（`test_e2e.py` 第 [4] 组），修复后它那 13 个用例**全部通过**；
* 本地测试总量：本项目自测 **37 项** + 码道智能体产出 **13 项**，全绿。
