# 01 · 缺口分析报告：码道缺什么，我们补什么

> 结论先行：**码道的"多会话并行"只解决了"同时跑"，没有解决"互相通信"。**

**筛选结论**：第 1 项（会话间通信）是唯一"完全缺失 + 可在学生项目范围内做出真实可用产物 +
能被现场演示"的缺口，因此作为本项目主题；第 2、3 项以"守护视图 + 任务协议"的形式部分补入。

## 五、为什么"补会话通信"这件事值得做

1. **是刚需而不是锦上添花**：码道官方鼓励"多会话并行"（个人体验版≤3、标准版及以上≤5），
   但没有任何会话间协调手段。并行度越高，人肉在会话之间搬运信息的成本越大。
2. **它把码道的"并行"变成了"协作"**：并行只是省时间，协作才能产出**一个人/一个会话做不出来**的交付。
3. **不侵入、可卸载**：全部通过官方支持的 MCP + 技能扩展点实现，**不改码道一行代码**，
   删掉配置即完全恢复。
4. **可复用可上架**：产物是通用能力（技能 + MCP 服务），其他同学装上就能用。

## 六、如何自行验证本报告的结论（3 分钟）

1. 打开码道 IDE，任意开两个会话（会话 A、会话 B）。
2. 在会话 A 里问：**"总线知道会话 B 现在在做什么吗？你能给会话 B 发消息吗？"**
   并对会话 B 问："会话 A 有没有给你派过活？"
3. 观察：两个会话之间**没有任何信息通道**，只能靠你人工复制粘贴。

这就是 agent-bus 要填的那块空白。装上它之后，重做第 2 步，两个会话就能互相喊话了
（操作步骤见 `docs/04-演示脚本.md`）。
